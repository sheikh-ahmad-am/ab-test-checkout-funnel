# A/B Test & Checkout Funnel Analysis

**Business question:** "We redesigned the checkout flow — did it actually lift
purchases, and should we ship it?"

A complete experiment analysis on 20,000 users: funnel diagnostics, a
significance-tested verdict on the redesign, segmentation that reveals
*where* it wins and loses, and an attribution comparison — all ending in a
ship / don't-ship recommendation.

## Why, how, what

**Why** — Redesigns usually ship on opinion and HiPPO approval. Without a
randomized test you cannot tell whether the new checkout helped, did nothing,
or quietly hurt a segment (as it did here on mobile). A proper A/B analysis
turns "I feel like it's better" into a measured, defensible decision.

**How** — (1) Generate 20,000 synthetic users in a 50/50 randomized
experiment with realistic funnel drop-off. (2) Sanity-check the experiment
(sample-ratio mismatch, covariate balance). (3) Compare stage-by-stage funnel
conversion. (4) Test the primary metric — purchase conversion — with a
two-proportion z-test, p-value and 95% confidence interval. (5) Segment the
lift by device and traffic source. (6) Compare first-touch vs last-touch
attribution. (7) Check the MoM baseline so the lift isn't riding a trend.

**What** — a decision-ready verdict (ship to desktop, hold mobile), a reusable
analysis script, five charts, and a SQL query pack (`sql/queries.sql`)
reproducing the funnel and conversion numbers. Every number below is the actual output of
`python/ab_analysis.py` (run 2026-09-26) — nothing is hand-waved.

## Analytics type

| Type | How this project uses it |
|---|---|
| **Diagnostic** (primary) | Did the redesign work, and where? The lift is isolated to desktop checkout stages; mobile is flat. |
| **Prescriptive** | The recommendation: ship to desktop traffic, keep mobile on control, investigate mobile friction separately. |
| **Descriptive** | What the funnel looks like — stage conversion rates, MoM baseline trend, attribution shares. |
| Predictive | Not claimed — this project measures what happened in the test; it does not forecast. |

## SQL analysis layer

The funnel and conversion numbers are also computed directly in SQL — the
same queries an analyst would run against an experiment events table.
[`sql/queries.sql`](sql/queries.sql) (MySQL-compatible) reproduces, all exact:

- **primary metric** — control 11.98% vs variant 14.50% conversion (+2.52pp lift)
- **by device** — desktop +7.00pp lift, mobile −0.72pp (flat)
- **funnel step** — checkout-started → payment-done: 65.89% vs 73.95% (+8.06pp gap)
- **full funnel** — stage-by-stage conversion for both groups

SQL handles the extraction, aggregation, and KPI computation; Python handles
the significance testing (z-test, p-values, confidence intervals, SRM checks)
and charts.

## Dataset

`data/ab_experiment.csv` — 20,000 users (seed 42, reproducible), generated by
`data/generate_ab_data.py`:

| Column | Description |
|---|---|
| user_id | Unique user id |
| variant | `control` (current checkout) / `variant` (redesign), ~50/50 |
| device | mobile / desktop |
| traffic_source | organic / paid / social / email (session channel) |
| first_touch / last_touch | attribution touchpoints (illustrative) |
| week | experiment week 1–4 |
| stage_reached | visited / added_to_cart / checkout_started / payment_done / purchased |
| purchased | 1 if the user completed a purchase |
| revenue | order value in INR (0 if not purchased) |

`data/baseline_monthly.csv` — 6 months of pre-experiment purchase conversion
(MoM context).

> All data is synthetic. No real users or revenue are involved.

## Methods

- **Sanity checks** — chi-square sample-ratio-mismatch test on the 50/50
  split; covariate balance (device, traffic source, week) across arms.
- **Funnel analysis** — conditional conversion at each stage, control vs variant.
- **Primary test** — two-proportion z-test on purchase conversion
  (pooled SE), two-sided p-value, 95% CI for the lift (unpooled SE).
- **Segmentation** — same test per device and per traffic source.
- **Attribution** — share of purchases credited per channel under first-touch
  vs last-touch (documented as illustrative, not causal).

## Results

### Sanity checks — the experiment is trustworthy

- Split: control 9,938 / variant 10,062. SRM chi-square = 0.769, **p = 0.38 → PASS**.
- Covariate balance: max arm difference 0.53% (device), 0.65% (source), 1.22% (week) — balanced.

### Funnel — the lift lives in the checkout stages

| Stage transition | Control | Variant | Delta |
|---|---|---|---|
| Visited → Added to cart | 34.10% | 34.85% | +0.75pp |
| Added to cart → Checkout started | 58.13% | 61.08% | +2.95pp |
| Checkout started → Payment done | 65.89% | 73.95% | **+8.06pp** |
| Payment done → Purchased | 91.76% | 92.11% | +0.35pp |

Cart-add behaviour is identical across arms — the redesign only moves the
checkout stages, exactly where a checkout redesign should bite.

### Primary metric — purchase conversion

- Control: **11.98%** · Variant: **14.50%**
- Absolute lift: **+2.52pp** (relative +21.0%)
- 95% CI for the lift: **[+1.58pp, +3.45pp]**
- Two-proportion z-test: **z = 5.25, p = 1.55e-07**
- **Verdict: SHIP** — statistically significant positive lift.
- Secondary: revenue/user Rs. 259 → Rs. 320 (+23.7%); AOV Rs. 2,159 → Rs. 2,208.

### Segmentation — where the variant wins and loses

| Segment | Lift | 95% CI | p-value | Significant? |
|---|---|---|---|---|
| Desktop | **+7.00pp** | [+5.38, +8.63] | < 0.001 | Yes |
| Mobile | −0.72pp | [−1.81, +0.37] | 0.198 | No |
| Email | +4.14pp | [+1.68, +6.59] | 0.001 | Yes |
| Paid | +2.86pp | [+1.14, +4.57] | 0.001 | Yes |
| Organic | +1.97pp | [+0.38, +3.57] | 0.016 | Yes |
| Social | +1.74pp | [−0.31, +3.79] | 0.097 | No |

The headline +2.52pp is carried by desktop. Mobile is flat-to-slightly-negative
and not significant — it must not block a desktop rollout, but it needs its
own diagnosis.

### Attribution (illustrative)

| Channel | First-touch share | Last-touch share |
|---|---|---|
| Organic | 36.8% | 35.0% |
| Social | 26.6% | 19.2% |
| Paid | 23.8% | 30.6% |
| Email | 12.8% | 15.2% |

First-touch rewards discovery (organic/social); last-touch rewards the closing
session (paid/email). Neither is "truth" — the right model depends on the
business question.

### MoM baseline

Purchase conversion sat flat at ~11.8–12.2% for the six months before the test —
the measured lift is not riding a pre-existing trend.

### Recommendation

**Ship the redesign to desktop traffic. Keep mobile on the current checkout
and investigate mobile friction separately.** Re-run with real traffic and
pre-register the primary metric and segments before launch.

## Caveats

- Synthetic data: effect sizes are illustrative. In production, size the test
  from a power calculation and pre-register the primary metric and segments
  *before* launch to avoid p-hacking by segmentation.
- The attribution comparison is illustrative — touchpoint data here is
  simulated, and attribution is not causal.
